# Phone Touchpad Plus 开源发布设计

日期：2026-09-29  
状态：已由用户最终确认

## 目标

将当前基于 Unrud/remote-touchpad 的中文增强版本，以
`ikedamiho41-hue3333333333/phone-touchpad-plus` 公开发布。项目面向希望把
iPhone 或其他智能手机用作 Ubuntu/Linux 多点触控板的用户，并提供可由
Codex 调用的安装、配置、诊断和维护 Skill。

发布工作不得改变本机正在运行的服务、配对密钥、访问地址、灵敏度、手势
配置或开机启动状态。

## 发布方式与许可证

- 使用 Unrud/remote-touchpad 的 GitHub Fork，公开仓库名称为
  `phone-touchpad-plus`，保留上游提交历史和 Fork 关系。
- 继续使用 GNU GPL-3.0，不删除 `COPYING`、原作者版权声明或源文件头。
- README 明确说明项目基于 Unrud/remote-touchpad，并区分上游能力与本项目
  修改。
- 修改版本带有显著的修改说明和日期；若将来提供二进制，同时提供对应源码、
  构建方法和许可证。
- Git 远程地址区分 `upstream` 与用户 Fork，避免向原作者仓库误推送。

## 项目标识与版本

- Go 模块路径改为
  `github.com/ikedamiho41-hue3333333333/phone-touchpad-plus`，内部导入同步更新，
  使用户能够从新仓库正常构建和安装。
- 程序显示名称改为 `Phone Touchpad Plus`，首个项目版本为 `v0.1.0`。
- README、关于信息和变更记录注明 `v0.1.0` 基于上游 Remote Touchpad
  `v1.5.5`，不得把上游版本误写成本项目独立版本。
- 构建时的版本信息必须来自一个可测试的统一来源，避免 CLI、README 和发布标签
  出现不同版本。

## 产品定位与支持范围

名称：Phone Touchpad Plus  
中文名称：手机触控板增强版

首版重点验证：

- Ubuntu 24.04；
- GNOME X11；
- iPhone Safari；
- 手机和电脑处于同一可信局域网。

首版功能：

- 中文手机界面；
- 单指移动和点击；
- 双指滚动与捏合缩放；
- 三指或四指切换当前工作区中的应用；
- GNOME 活动概览和显示桌面；
- 独立的鼠标移动与滚动灵敏度；
- 二维码配对；
- 用户级 systemd 自动启动；
- 针对双指滚动误触发缩放和输入 `=` 的回归修复。

上游的 Windows、macOS 和 Wayland 代码保留，但文档必须明确标注这些平台的
中文增强功能尚未由本项目完成验证。

服务配置向手机端报告可用能力。手机仅显示当前后端支持的增强手势；如果后端未
实现 `GestureController`，基础移动、点击和滚动继续可用，但增强手势按钮隐藏或
禁用。`v0.1.0` 不承诺 Windows、macOS 或 Wayland 的增强手势支持。

## 安装与生命周期

`scripts/install.sh`：

1. 检查操作系统、GNOME/X11、Go 和 X11 构建依赖；
2. 对需要系统级依赖的动作明确请求用户授权；
3. 从源码构建并安装到当前用户目录；
4. 为每台电脑生成独立的随机配对密钥；
5. 创建用户级 systemd 服务并设为登录后自动启动；
6. 输出手机访问地址和配对二维码；
7. 检测已有安装，不静默覆盖用户配置。

安装器必须处理以下环境差异：

- 从运行环境探测当前用户、UID、`DISPLAY` 和有效的 `XAUTHORITY`，不写死 UID
  或 GDM 路径；
- 检查 `go.mod` 要求的 Go 版本。系统 Go 版本不足时停止并给出可验证的安装
  指引，不静默执行来源不明的工具链脚本；
- 检查 X11 构建依赖并列出缺失包，只有获得授权后才调用系统包管理器；
- 支持 `--dry-run`，输出将要创建、修改和启动的内容，但不写文件、不安装依赖、
  不启动服务；
- 支持显式升级模式。普通安装遇到已有配置时停止；升级模式保留密钥、灵敏度和
  用户配置，并在替换前验证新二进制可执行；
- 使用临时文件加原子替换，安装失败时不得留下半写入的程序或服务文件。

## 配置与密钥保存

- 程序新增从受限文件读取密钥的方式，例如 `-secret-file`；公开安装流程不得把
  明文密钥放入 systemd `ExecStart` 或普通命令行参数。
- 配对密钥保存到用户配置目录中的独立文件，权限为 `0600`；配置目录权限至少为
  `0700`。
- systemd 用户服务只引用密钥文件路径。诊断输出、日志和错误消息始终遮盖密钥。
- 灵敏度等非秘密设置使用独立配置或环境文件，升级时保留。默认移动和滚动倍率
  为上游值；公开安装器不继承开发机器当前的两倍移动速度。

## 网络地址与二维码

- 地址选择优先使用默认网关对应的、处于工作状态的私有局域网接口。
- 排除回环、链路本地、容器、隧道和常见 VPN 接口；无法确定时列出候选地址，
  而不是静默选择第一个地址。
- 优先展示可解析的 `<hostname>.local` 地址，同时展示局域网 IPv4 备用地址。
- 二维码使用已选择的手机可访问地址生成。二维码文件存放在用户数据目录，不进入
  Git 仓库。
- 安装完成后的验证必须从实际监听端口读取页面，并确认 URL 中保留配对片段。

`scripts/doctor.sh` 只执行只读诊断，检查服务状态、端口、图形会话、网络地址、
默认路由、mDNS 解析、所需文件和近期错误，并对密钥进行遮盖。诊断结果区分
“服务未运行”“手机不可达地址”“图形会话注入失败”和“认证失败”，不能只给出
笼统的连接失败。

`scripts/uninstall.sh` 默认停止服务并删除程序文件，但保留用户配置。仅在用户
明确指定清除配置时，才删除配置和配对信息。

首版发布源码和本地构建安装脚本，不提供未经多环境验证的预编译二进制。

安装器和卸载器的自动测试使用临时 `HOME`、临时安装前缀、独立端口和模拟的
systemd 命令。发布整理过程中不得运行会覆盖当前
`phone-magic-trackpad.service` 的测试；对本机现有服务仅允许只读状态验证。

## Skill 设计

Skill 名称为 `phone-touchpad-plus`，采用正常自动发现方式。它在用户提出安装、
配对、调节灵敏度、查看状态、诊断连接、更新或卸载 Phone Touchpad Plus 时触发。

Skill 负责选择并调用仓库脚本、解释诊断结果以及验证服务状态。它不承担持续的
鼠标事件传输；实际控制仍由后台服务完成。

Skill 必须保留授权边界：只读诊断可直接执行；安装系统依赖、修改防火墙、重启
服务、更新或卸载前必须取得相应授权。失败时报告可验证证据，不循环执行高风险
操作。

## 隐私与安全

- 除公开的 GitHub 仓库所有者名称外，仓库不得包含真实配对密钥、局域网 IP、
  二维码、本机操作系统用户名、主机名或个人绝对路径。
- `.gitignore` 覆盖本地配置、密钥、二维码、构建产物、临时目录和编辑器文件，
  但不忽略公开服务模板与测试夹具。
- 文档和脚本使用 `$HOME`、运行时探测或参数，不写死开发机器目录。
- 生成的密钥和配置仅保存在目标用户目录，并使用用户级文件权限。
- README 明确提示：当前连接带配对密钥验证但不提供 TLS，必须仅在可信局域网
  使用。
- 示例二维码和地址只能使用虚构数据。

## 测试与发布门槛

GitHub Actions 和本地发布检查覆盖：

- `go test -tags=x11 ./...`；
- `go test -tags=null ./...`；
- JavaScript 语法检查；
- 双指滚动漂移不触发缩放手势的回归测试；
- 左右滑生成当前工作区应用切换快捷键的回归测试；
- Shell 脚本静态检查；
- 敏感信息扫描；
- GPL 文件、上游署名和修改说明存在性检查。

实时协议测试必须作为独立 CI 步骤执行：先使用 Null 后端、固定测试密钥和独立
端口启动测试服务，等待端口就绪，再运行带 `integration` 标签的测试并在结束后
清理进程。CI 不得把仅编译了测试文件误报为已经执行协议测试。

手势回归测试使用 Node 实际执行测试文件，而不只进行语法检查。安装脚本除
ShellCheck 外，还必须在临时目录运行 `--dry-run` 和无 systemd 副作用的安装生命周期
测试。

在发布提交前执行完整仓库扫描，包括已跟踪、未跟踪和待提交文件。扫描至少覆盖
配对密钥模式、私有 IP、开发者用户名、主机名、个人绝对路径、二维码和本地服务
配置。发布提交按“应用行为、测试、安装工具、Skill、文档”拆分，禁止把未经审阅
的脏工作区一次性提交。

首个公开版本标记为 `v0.1.0`。只有本地和 CI 检查全部通过后才创建标签。发布后
继续保留上游远程地址，并以回归测试驱动后续手势修复。

`v0.1.0` 明确不包含以下工作：自动 TLS、预编译二进制、自动更新，以及
Windows、macOS、Wayland 的完整增强手势。这些能力在实际平台测试和威胁模型评审
完成后再进入后续版本。
